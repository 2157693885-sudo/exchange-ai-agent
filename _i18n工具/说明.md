## 用法

先起本地服务（脚本默认指向 `http://127.0.0.1:8901`）：

```bash
cd "02_产品系统与可运行交互原型/02_网页端全真系统"
python -m http.server 8901 --bind 127.0.0.1
```

再在**项目根**（`02_网页端全真系统/`）下运行：

```bash
node "_i18n工具/1_审计内容翻译完整度.js"
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe "_i18n工具/2_查缺失词条.py"
~/.workbuddy/binaries/python/envs/default/Scripts/python.exe "_i18n工具/3_十语种浏览器验证.py"
```

> 脚本已按子目录修正路径基准，**必须在项目根下运行**，不要在工具目录里跑。

## 四条必须遵守的约定

**1. 语言优先级链：目标语 → 英文 → 中文。**
`KB.L(obj, field, lang)` 取内容字段，`L10N.t(key, lang)` 取界面文案。
新增任何内容字段，**英文回退必须补齐**（`title_en` / `label_en` / `channel_en` / `risk_en` / `docs_en`），否则非中文语种会露出中文。

**2. 内容层多语走 `kb-i18n-*.js` 内容包，不往数据文件里塞 `_ar`/`_ru` 字段。**
内容包按 `id` 匹配，匹配范围已覆盖 `KB.MATTERS`（内置 27 条）+ `SYSU_PRESET_KB`（校本 5 条）。
注意：**内容包可能先于目标数据加载**，此时译文会被静默丢弃。
`kb-school-sysu.js` 末尾会调 `KBI18N.applyAll()` 补齐，新增含多语内容的数据文件也请照做。

**3. RTL 一律用逻辑属性，不写 `[dir="rtl"]` 覆盖。**
- 用 `margin-inline-start` / `padding-inline-end` / `inset-inline-start` / `text-align: start`
- 只有两类例外必须物理化，已在 `base.css` 的「RTL 方向适配」段注明：
  - `background-position`（CSS 无逻辑版本）→ 补一条 `[dir="rtl"]` 覆盖
  - `safe-area-inset-*`（设备物理边缘）→ 保持 `padding-left/right`

**4. 预置数据不落盘，只有用户自建数据才持久化。**
`localKbItems()` 里预置条目每次都从 `kb-school-sysu.js` 现读。
若把预置条目也写进 `localStorage`，旧缓存会把「尚未补齐译文的旧版本」一直带下去，
后来补的十语译文永远不生效。机构端保存时已按 `!_preset` 过滤。

## 关于语言条顺序（结论：保持镜像，不改）

RTL 下语言条整体镜像，**但读取次序与 LTR 完全一致**——十语种实测均为
`zh,en,ru,ar,fr,es,vi,th,my,ms`。

即：阿拉伯语用户从右往左读到的序列，与中文用户从左往右读到的序列相同。
`العربية` 在两种方向下都是第 4 个。这意味着镜像不会让用户多付出一次搜索成本，
正是 RTL 布局应有的行为，无需额外覆盖。

（工具 3 会断言这一点；若哪天读序变了，说明有样式把顺序写死了。）
